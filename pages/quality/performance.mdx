# Performance & Scale

Set numeric targets, measure them every release, and fail the release if they regress.

## Suggested targets

| Metric | Target |
| --- | --- |
| Cold start to usable (desktop) | under 3 s |
| Cold start to usable (mobile) | under 2 s |
| Message send to delivery (same region) | under 300 ms p95 |
| Room switch | under 200 ms |
| Call connect time | under 3 s |
| Desktop memory after 8 hours | under 1 GB, no steady growth |
| Mobile battery, 1 hour idle in background | under 2% |
| Server uptime | 99.9% or better |

## Test cases

| ID | Priority | Scenario | Expected |
| --- | --- | --- | --- |
| PRF-01 | P0 | Account with 1,000 rooms and 50,000 messages | Starts within target |
| PRF-02 | P0 | Room with 10,000 members | Member list, mentions and sending stay fast |
| PRF-03 | P1 | Scroll back 5 years of history | Smooth, no memory blow-up |
| PRF-04 | P1 | Room with 1,000 messages per minute | UI keeps up, no freeze |
| PRF-05 | P0 | Load test: N concurrent users sending | Server latency stays in target; find the breaking point |
| PRF-06 | P1 | Group call load: 50 video participants | Server CPU / bandwidth measured, client still usable |
| PRF-07 | P1 | Leave app open 24 hours | No memory leak |
| PRF-08 | P1 | Low-end Android (2 GB RAM) | Usable |
| PRF-09 | P1 | Server failover / database restart | Short blip, no data loss |
| PRF-10 | P1 | Backup and restore drill | Restore works and is timed |
